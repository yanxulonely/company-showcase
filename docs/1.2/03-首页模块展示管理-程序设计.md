## 2. 数据层

与规划一致：`settings.module_visibility` JSON 字符串，种子默认全开。

`PUT /api/settings` 时若 body 含 `module_visibility`，走 `normalizeModuleVisibility()`：`hero`、`contact` 强制 `true`。

**按字段局部更新**：各管理页只改一个 key 时，前端先读当前 visibility，改一项后再整包 PUT，避免覆盖其他模块：

```js
async function setModuleVisible(moduleId, visible) {
  const current = parseModuleVisibility(appStore.settings)
  current[moduleId] = visible
  await appStore.updateSettings({
    module_visibility: JSON.stringify(current),
  })
}
```

function isModuleVisible(id) {
  return moduleVisibility.value[id] !== false

function visibleNavModules() {
  return SITE_MODULES.filter(m => m.navLabel && isModuleVisible(m.id))

## 4. 可复用组件 `ModuleVisibilityToggle.vue`

**路径**：`client/src/components/admin/ModuleVisibilityToggle.vue`

**Props**：

| Prop | 说明 |
|------|------|
| `moduleId` | 如 `'cases'`、`'activities'` |
| `label` | 可选，默认「在首页展示」 |

**行为**：

- 从 `appStore.isModuleVisible(moduleId)` 初始化开关状态
- `required: true` 时开关 disabled，附文案「首页必备模块」
- `@change` → `appStore.setModuleVisible(moduleId, val)` → 成功/失败提示
- 下方一行小字：`关闭后首页不显示「xxx」区块，导航同步隐藏；不影响独立页面访问。`（活动模块这句尤其重要）

**用法示例**（案例管理页顶部）：

```vue
<ModuleVisibilityToggle module-id="cases" />
```

## 6. 前台改造

### 6.1 `HomePage.vue`

各 Section 加 `v-if="appStore.isModuleVisible('xxx')"`（与规划一致）。

### 6.2 `Navbar.vue`

```js
const navLinks = computed(() =>
  appStore.visibleNavModules().map(m => ({ label: m.navLabel, href: m.anchor }))
)
// 首页锚点：hero 可见时保留「首页」
// 若 hero 必显，始终有 #home
```

首页导航项：当 `hero` 可见时显示 `{ label: '首页', href: '#home' }`（hero 必显，实际上一直有）。

「联系我们」：`contact` 必显，按钮始终保留。

### 6.3 路由 — 不拦截活动

**删除/不做**针对 `/activities` 的 `beforeEach` 守卫。独立活动页、分享落地页与首页展示开关无关。

### 6.4 启动时拉 settings

`main.js` 启动时 `await appStore.fetchSettings()`，保证首屏 HomePage / Navbar 读到正确 visibility。
