# v1.1 规划：活动模块 + 项目整体架构升级

## 背景与目标

在现有营销官网（案例、设计师、能力、评价等）基础上，新增「活动」模块：

- 展示公司举办/参与的活动
- 支持点击查看活动详情
- 活动详情页可作为独立页面对外分享（链接 / 二维码）

同时结合本次开发对全站架构做一次系统性梳理，输出可执行的升级建议清单，供后续版本排期。

## 确认的产品形态（已与需求方沟通确认）

- 首页新增「活动」Section 做曝光展示，同时提供独立的**活动列表页** + **活动详情页**路由，用于日常浏览与分享。
- 详情页对外分享时，微信/QQ/微博等场景需要显示**该活动自己的标题和封面图**（动态卡片），不能只显示网站默认标题。
- 报名不单做，复用现有「联系我们」线索表单（类似设计师模块 `preferredDesigner` 的预填模式）。

## 架构关键决策：如何实现"动态分享卡片"

当前站点是纯 SPA，用 `#/` Hash 路由（`client/src/router/index.js` 的 `createWebHashHistory()`），`index.html` 只有静态 `<title>`。Hash 片段**不会发送到服务器**，服务器无法根据 `#/activities/5` 判断该渲染哪条活动的 meta；而微信/QQ/Telegram 等抓取分享卡片时**不执行 JS**，只读首屏 HTML 里的 `<title>` 和 `og:*` meta。

如果把整站迁到 History 模式 + 完整 SSR，工作量和部署改造都很大（现有约定是"生产环境 Express 不托管 client/dist，需要反代"，这个约定也要打破）。

**采用轻量方案：新增一个独立的"分享落地页"路由，只服务于分享场景，不改动现有 SPA 路由模式。**

```mermaid
flowchart LR
    User[用户浏览网站] -->|"点击活动卡片(站内)"| SpaRoute["SPA路由 #/activities/:id (无刷新)"]
    Admin["管理员/详情页"] -->|"点击\"分享\"生成"| ShareLink["分享链接 /share/activities/:id"]
    ShareLink --> Qr["前端现场生成二维码(指向分享链接)"]
    ShareLink -->|"粘贴到微信/QQ/微博"| Crawler["聊天工具抓取器(读取HTML头,不跑JS)"]
    Crawler --> SsrRoute["Express路由 GET /share/activities/:id"]
    SsrRoute -->|"查库拼接HTML(og:title/og:image/正文)"| RenderedHtml[服务端渲染的静态详情HTML]
    RenderedHtml -->|"页内按钮跳转"| SpaRoute
```

- 站内浏览：走 SPA 路由 `#/activities/:id`，体验流畅、无刷新。
- 对外分享：链接与二维码都指向服务端渲染的 `GET /share/activities/:id`，返回一份不依赖 JS 的完整 HTML（含 `og:title`/`og:description`/`og:image`、活动标题、封面图、时间地点、正文），页面里放"进入官网查看更多活动/联系咨询"按钮跳回 SPA。这样绝大多数分享抓取（微信默认抓取、QQ/微博/Telegram 的 Open Graph 抓取）都能拿到正确的标题和图片。
- **局限说明**：微信内**自定义**分享卡片摘要图（`wx.updateAppMessageShareData`）需要认证公众号 + JS-SDK 签名接口，涉及资质与 `access_token`/`jsapi_ticket` 管理，属于更大投入，本版本不做，列入后续可选项。多数场景下靠服务端渲染的 `og:*`/`title` 已经足够覆盖。

## 范围划分

| 范围 | 内容 |
|------|------|
| 本版本要做 | 活动数据模型、活动 CRUD 接口、活动前台列表/详情/首页展示、分享落地页(SSR)、二维码分享、后台管理、报名复用联系表单 |
